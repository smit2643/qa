# Reporting Module

Location: `backend/modules/reporting/`

Handles run history, per-result detail retrieval, and on-demand AI failure analysis.

---

## Files

| File | Responsibility |
|---|---|
| `service.py` | Query run/result data, generate AI failure summaries |
| `router.py` | Endpoints: run detail, suite run history, analyze failure |

---

## Endpoints

| Endpoint | Description |
|---|---|
| `GET /reporting/runs/{run_id}` | Full run with all test results, video URLs, AI summaries |
| `GET /reporting/suites/{suite_id}/runs` | Run history (latest 20) |
| `POST /reporting/results/{result_id}/analyze` | Generate AI summary for a failed result |

---

## AI Failure Analysis

When a test fails, the runner posts the raw error message and stack trace. The reporting module can generate a human-readable summary on demand via `POST /reporting/results/{result_id}/analyze`.

The summary is generated by Claude using the test name, error message, and test code as context. It is stored in `test_results.ai_summary` and returned on all subsequent fetches of that result.

Example summary:
> "The checkout button was not found. The selector `div.btn-checkout` appears to have been renamed in a recent deploy. The element exists in the accessibility tree as `role=button, name='Complete Purchase'`."

---

## Result Status Values

| Status | Meaning |
|---|---|
| `passed` | Test completed without error |
| `failed` | Test threw an exception or assertion failed |
| `flaky` | Test passed on retry after initial failure (set by runner) |

---

## Run Status Transitions

```
queued → running → passed
                 ↘ failed
```

A run transitions from `running` to `passed` or `failed` when the last result is posted by the runner. A run is `passed` only if **all** results passed.
